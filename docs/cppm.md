# cppm — ClearPass NAC

Aruba ClearPass Policy Manager spoke. Repo: `cppm`. `module_type = "nac"`. See [architecture-topology.md](architecture-topology.md).

## Role & module_type

NAC spoke — endpoint auditing, session/access-tracker monitoring, and a hub-orchestrated IPAM→ClearPass endpoint sync. Source for the realtime NAC→IPAM reverse sync (`CPPM_GET_RECENT_SESSIONS` → `NETBOX_SYNC_ACCESS_TRACKER` on the netbox spoke).

## Entrypoints

`python3 -m src.control_plane` (`CPPMControlPlane`); spoke `CPPMSpoke` (**no base class** — not `BaseSpoke`); falls back to `run_standalone_mode()` (FastAPI `0.0.0.0:8000`, `/status`) if `--hub` omitted. systemd `lm-cppm.service`. Installer `install.sh` (clones to `/opt/lm/cppm`, venv, `.env`, unit; `PYTHONPATH=$INSTALL_DIR:$INSTALL_DIR/core/src:$INSTALL_DIR/cppm/src`). `src/main.py` is a standalone demo script, not the entrypoint.

## Ports / backends

Talk to ClearPass REST (`CPPMClient`, `src/client.py`, `requests.Session`, TLS verify configurable via `verify_ssl` / `LM_CPPM_VERIFY_TLS`). Auth: OAuth2 (`POST /api/oauth`) with **password grant preferred over client_credentials** when user creds are available (inherits the user's operator profile vs the API client's restricted profile); falls back to basic auth. Token cached with expiry (`expires_in`, 30s skew); a 401 on a cached token drops it, fetches a new one and retries the call once. The base URL is always `https://`: a host configured as `http://` is upgraded (with a warning) so credentials never travel in cleartext. Each configuration (host, credentials, TLS verify, its own `requests.Session` and its own cached token) is one `_Conn` that `update_config` replaces whole; every HTTP request, including its token fetch, basic-auth fallback and 401 retry, and each `TEST_AUTH` run, uses the configuration it started with, so a reconfiguration mid-call never sends one appliance's token, password or grant to the other, or changes the TLS mode of a call in flight. A command that makes several requests (for example the NAC status counts) can still straddle a switch: each request is whole, the command is not. Endpoints: `/api/session` (access tracker / recent sessions / user sessions / NAC status), `/api/endpoint` (device DB, by-MAC, by-IP, upsert/sync), `/api/role`. Standalone mode serves :8000.

## Environment variables

`.env.example` (loaded by `client.py`'s hand-rolled `load_dotenv()`): `CPPM_HOST`, `CPPM_CLIENT_ID`, `CPPM_CLIENT_SECRET`, `CPPM_USER`, `CPPM_PASS`; plus `SPOKE_ID`, `SPOKE_SECRET`, `HUB_URL`, `LM_CPPM_VERIFY_TLS`. Connection config also pushable via `UPDATE_CONFIG`.

## Install flags

`install.sh`: `--hub`, `--id`/`--name`, `--secret`, `--hub-secret`, `--all-prereqs` (no-op). Keeps default PSK `lm-secret` for zero-touch. A re-run updates only the keys it owns in `.env`: a flag given wins, and `--hub`/`--secret`/`--hub-secret` left out keep their `.env` value; `SPOKE_ID` is reset from `--id` or the hostname; other lines are kept. `HUB_SECRET` is written (the unit passes `--hub-secret=$HUB_SECRET`). `.env` is `svc_lm`-owned, mode 0600; `svc_lm` is created if missing. The `.env` update runs as `svc_lm` (`runuser`) under `flock` on `.env.lock`, the lock the spoke takes when it rotates a secret.

## Key commands / handlers (`spoke.handle_command`, via `run_in_executor` — `CPPMQueries` is sync `requests`)

`GET_VERSION`, `CPPM_REFRESH_CACHE`, `UPDATE_CONFIG`, `TEST_AUTH` (tries every OAuth candidate in a worker thread, reports per-attempt; a success shows only `token_type`/`expires_in`/`scope`, never the token), `PROBE_API` (raw `_request`, **GET only**: any other method is refused with ERROR). The command log masks every field whose name contains `pass`, `secret`, `token`, `key` or `psk`, and any PEM private key text. Cached: `CPPM_GET_ACCESS_TRACKER`, `CPPM_GET_DEVICE_DATABASE`, `CPPM_GET_NAC_STATUS`. Live: `CPPM_GET_RECENT_SESSIONS` (last `lookback_minutes` default 2 — **not cached**, time-sensitive, called ~60s by the hub realtime NAC→IPAM loop), `CPPM_GET_SYSTEM_HEALTH`, `GET_DEVICE` (by MAC), `LIST_ENDPOINTS`, `GET_ENDPOINT_DETAIL`, `GET_DEVICE_SESSIONS`, `GET_USER_SESSIONS`, `GET_LOGS` (auth logs by start/end), `LIST_ROLES`, `SEARCH_SESSIONS`, `CPPM_SYNC_ENDPOINTS` (hub-orchestrated IPAM→ClearPass: upserts a tenant's endpoint batch tagged `NetBox_Tenant_Name`/`_ID` + `Tenant` + `IP Address`/`Hostname`/`status:Known`; `replace=True` deletes endpoints previously tagged with this tenant absent from the batch (it keeps an endpoint an IP-only record resolved to, and any endpoint carrying the IP of an IP-only record whose lookup failed or found nothing; a page of the endpoint list that fails to load, is not a page of endpoints, ends the list before its reported count, reports a count below the rows already returned or different from the first page's (the inventory changed mid-scan), or is a full page with no count aborts the removal with nothing deleted; any removal failure, including each stale endpoint whose DELETE fails, reports `ERROR`, and one failed DELETE does not stop the others); MAC-keyed upsert with IP fallback; an IP-only record with no existing endpoint is skipped only when the IP → endpoint scan covered the whole inventory, and counts as an error when that scan failed, returned something other than a page, ended before its count, reported a count below its rows or different from the first page's, or hit `SYNC_SCAN_CAP` (IPs found on the rows it did read still resolve); an IP-only record borrows a MAC from a live session (`framedipaddress`) only after that scan covered the whole inventory, so a partial scan never creates a second endpoint for an IP that another endpoint may carry; per-endpoint failures counted, never raised), `CPPM_SYNC_NADS` (hub-orchestrated: one Network Device per tenant subnet named `LM-<tenant>-<subnet>` with the tenant's `radius_secret`/`tacacs_secret`; owns only devices whose description starts `LM-managed tenant=<tenant>` and deletes those whose subnet is gone), `INSTALL_CERT` (hub-brokered ACME TLS certificate delivery, PKCS#12 conversion, Certificate Trust List / CTL root enrollment, and HTTPS/RADIUS service binding).

## Key files

`src/control_plane.py` (+ standalone FastAPI), `src/spoke.py` (`CPPMSpoke` non-BaseSpoke, dispatch, cache, `SENSITIVE_KEYS` masking), `src/client.py` (`CPPMClient`: `load_dotenv`, OAuth `_get_token`/`_try_oauth`, `_request`/`query`, `update_config`, 204-tolerant empty-body, TLS verification toggles), `src/queries.py` (`CPPMQueries`: all the get_* + `sync_endpoints` + `import_cert` + helpers `_nas_*`, `_iso_dt`, `_norm_mac`, `_coerce_attrs`, `_endpoint_ips`, `_build_ip/mac_endpoint_map`, `_get_endpoint_by_ip`, `_upsert_endpoint`), `src/main.py` (demo), `install.sh`, `API_SPEC.md`, `requirements.txt`, `VERSION`.

## Notable behaviors & gotchas

- **`CPPMSpoke` is non-BaseSpoke** — `class CPPMSpoke:` (no `BaseSpoke` base). Implements `spoke_id`/`config`/`get_version`/`handle_command` itself; registered into the control plane's `modules` dict. The control plane also locally overrides `register_module` (same pattern as ldap). On the hub side, the agent-spoke role loader wraps it with `_RoleAdapter`.
- **Endpoint IP fallback scan** — ClearPass's `ip_address` filter only matches the first-class field; `_endpoint_ips` collects IPs from arbitrary attribute names and `_build_ip/mac_endpoint_map` do bounded paged scans (`ENDPOINT_SCAN_CAP` / a larger sync cap) so static-IP devices whose IP lives under a profiler-populated attribute are still matched and their MAC reused.
- **In-memory cache** for `CPPM_GET_ACCESS_TRACKER`/`CPPM_GET_DEVICE_DATABASE`/`CPPM_GET_NAC_STATUS` only; `CPPM_GET_RECENT_SESSIONS` deliberately uncached (realtime loop). `UPDATE_CONFIG` that changes the host or any credential (user, password, client_id, client_secret) drops the cache (an identical re-push keeps it), and a refresh that started before the change does not store its results.
- **Read-only ClearPass node** — a token reply containing "Replication: Writes on" (seen as HTTP 500 `SQLSTATE[P0001]: Raise exception: 7 ERROR: Replication: Writes on t…`) means the node refused a database write, so it cannot issue an OAuth token: it is likely a subscriber, or cut off from its publisher. Point LM at the cluster's publisher. The spoke adds that hint to the grant's warning, to the "All OAuth2 attempts failed" error and, ahead of ClearPass's reply, to the error message of the call whose own token run failed this way and which was then sent without a token and refused (for example 403); a token run made for another call never adds or removes it; `TEST_AUTH` shows it as the attempt's `hint`. Other failures read as before.
- **NAC status never shows a failed count as 0** — in `CPPM_GET_NAC_STATUS` a count whose query failed is `null` (the WebUI shows "—"); when every count fails it returns the first query's error (or "ClearPass returned no counts"), and neither the spoke nor the hub caches it. The hub's `/api/cppm/nac-status` keeps serving the last good counts it has, and answers with an error when it has none (the page then shows "—").
- **Access Tracker history** — `CPPM_GET_ACCESS_TRACKER` without `lookback_hours` stays active-only for dashboard counts. The WebUI sends `lookback_hours=24` to include sessions started during the prior 24 hours, whether active or closed. Older spokes ignore the optional field and return active sessions only until updated.
- **Token strategy** — password grant with `client_id` (configured, then `ClearPass`), then password grant with no `client_id`, then `client_credentials` (user operator profile > API client profile). Tolerates empty 204 bodies on DELETE.
- **`CPPM_SYNC_ENDPOINTS` tenant tagging** uses the same attribute names the at-auth-time Context Server Action uses (`NetBox_Tenant_Name` etc.) so an Enforcement Policy matches the tenant whether the endpoint was synced in advance or tagged at auth time.
- **`INSTALL_CERT` Certificate Trust List & PKCS#12 generation** — installs leaf, intermediate, and detected root CAs (ISRG Root X1/X2) into ClearPass CTL before binding server certificate to avoid 422 errors.
